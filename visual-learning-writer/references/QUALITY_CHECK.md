# Before delivering a lesson

## Source completeness (mandatory)

- List the source's important ideas and mark each as included, linked, deliberately deferred or not supported by the source. This check is internal; report omissions that materially affect understanding.
- Verify that any prerequisite **used** by the new concept is explained or meaningfully refreshed (e.g. TF, DF, IDF, TF-IDF in the BM25 lesson). Mentioning a term is **not** the same as teaching it.
- Preserve the source's scope, numbers, sample size, library/version, caveats and result-vs-inference distinctions. Don't flatten disagreement between sources into false certainty.
- If something isn't in the supplied source, label it as added background and use reliable verification when appropriate; never attribute it falsely to the project.
- Honor user decisions about additional background. No unsolicited full companion concept lessons.

## Learnability

- Does an unfamiliar reader understand the purpose from the first screen?
- Are undefined acronyms and symbols explained at the point of use?
- Does each new technical term follow from an already explained idea?
- Is at least one concrete example worked through from start to finish?
- Is the intuitive explanation accurate, not an oversimplification that becomes wrong later?
- Could 20% of the words be removed without losing understanding? If yes, edit.
- Is the full mode actually deeper (mechanism, math or decisions), not simply padded?

## Visual and functional QA

- Does the page design actually fit this topic rather than mechanically copying the BM25 example? Are the palette, layout, diagrams and interactions chosen to improve understanding?

- Every visual has a point; axes, legends and units are understandable.
- Sample values in graphs agree with the formula; measured values agree with cited source.
- Try short/full switching, all buttons/sliders, any quiz feedback, mobile width, long text, print readability when possible.
- Self-contained output uses no remote fonts, images, scripts or CSS; no broken local links if promised offline.
- Avoid inaccessible color-only distinctions, contrast failures, overlapping labels and horizontal scrolling on phones.

## Reporting

Deliver the actual output path and a short coverage statement. If browser interactions were not run, state this plainly. Do not claim exact file locations or successful tests without checking.
